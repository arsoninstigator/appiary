# appiary

appiary is a middle saas layer that packages web apps generated by tools like lovable, base44, and replit into native ios and android apps. it automates configuration, previewing, and deployment without hosting physical mac infrastructure.

## how it works

1. **client runtime wrapper** — an internal, hidden native project template built with [capacitor](https://capacitorjs.com). when a user submits a lovable web url, the backend injects it into `capacitor.config.json` under `server.url`, wrapping the web app instantly inside a native webview with bridging enabled. see `src/wrapper.js` and `template/`.
2. **interactive browser preview** — a headless debug build is pushed via api to a simulator streaming service ([appetize.io](https://appetize.io); simmer/tapflow as oss fallbacks). the dashboard embeds the resulting iframe so the user interacts with their live app at 60fps in the browser. see `src/appetize.js`.
3. **cloud compilation intermediary** — no mac minis. clicking "deploy" triggers a `repository_dispatch` to the github actions api; an ephemeral hosted macos runner spins up on demand for the heavy native compile. see `src/github.js` and `.github/workflows/appiary-build.yml`.
4. **automated signing and submission** — inside the runner, fastlane runs `match` (headless provisioning), `gym` (production binary), and `deliver` (push to testflight / play console). see `template/fastlane/Fastfile`.

## credential routing

sensitive store credentials (apple `.p8` keys, issuer ids, match passwords, play service accounts) are stored with row-level envelope encryption (aes-256-gcm, per-row dek wrapped by the master key). they are decrypted in memory only during the webhook execution and injected into the github action environment via a **single-use handoff token**: the runner redeems it once against `POST /redeem` (ttl-bound, job-bound, burned on use), and shreds every secret file when the job ends. secrets never travel inside the dispatch payload. see `src/vault.js` and `docs/credential-flow.md`.

## layout

```
appiary/
  src/
    index.js          cli entry (wrap / deploy)
    config.js         env config
    log.js            lowercase logger with credential scrubbing
    wrapper.js        step 1: capacitor config injection
    appetize.js       step 2: simulator preview client
    github.js         step 3: repository dispatch orchestration
    pipeline.js       job state machine: wrapped -> previewing -> dispatched -> building -> submitted
    vault.js           credential vault + single-use handoff tokens
    vault/crypto.js   envelope encryption primitives
    handoff-server.js the two-route api the runner talks to
    store.js          pluggable kv store (swap for the app database)
  template/           hidden capacitor native project template + fastlane lanes
  .github/workflows/  the runner-side build workflow
  tests/selftest.js   self-test suite (no network needed)
  docs/               architecture and credential flow
```

## usage

```sh
# wrap a web app
APPIARY_MASTER_KEY=... node src/index.js wrap \
  --url https://demo.lovable.app \
  --app-id com.example.demo \
  --app-name "Demo App"

# dispatch a cloud compile (needs github repo + token)
APPIARY_GITHUB_TOKEN=... APPIARY_GITHUB_REPO=appiary/cloud \
APPIARY_MASTER_KEY=... node src/index.js deploy \
  --job job-....json --credentials creds.json --platform ios

# self-tests
npm test
```

## intake

three ways in: published web urls (wrap), git repos on github/gitlab/bitbucket/gitea (bundle), or zip uploads (bundle). see docs/architecture.md, step 0. once shipped, the app's device behavior (notifications, permission states, accessibility) is documented in docs/device-runtime.md and its stores and update channels in docs/distribution-channels.md. whether a game can ship on the shell has its own honest verdict in docs/games.md.

## roadmap

see `docs/horizon.md` for the versioned plan: v1 capacitor wrap (now), v2 react native / expo, v3 flutter late stage on the horizon.

## status

working core: all four steps implemented and covered by 11 self-tests (encryption roundtrip + tamper detection, plaintext-never-stored, single-use handoff redeem/burn/ttl, capacitor injection + validation, appetize publish + embed, dispatch payload shape, end-to-end pipeline state machine, handoff server over real http, log redaction, runner workflow ordering). the native template's xcode/gradle projects and the dashboard ui are the next layer.

## pricing

per push, usage-based, no subscriptions. ios push $48.99, android push $28.99, both platforms $77.98. a push is any pipeline run that produces a new store artifact —
first build and updates cost the same, wrap-mode content edits are free
(they never rebuild). previews are bundled with hard minute caps. see
docs/cost-model.md for the margin math.
